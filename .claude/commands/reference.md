---
description: YouTube の参考曲から雰囲気(テンポ・キー・コード機能・盛り上がり等)を分析し、作りたい曲のイメージを固める
argument-hint: "<曲名> <YouTubeのURL>"
---

参考曲の分析を行い、ユーザーが作りたい曲のイメージを言葉にする手伝いをする。引数: $ARGUMENTS(`<song> <url>`。足りなければ `AskUserQuestion` で聞く)

1. 最初に `docs/reference-analysis.md` の注意(私的な分析のみ・複製しない・公開しない)を1〜2行で伝える。対象は YouTube の単体動画(10 分以内)。
2. `projects/<song>/` が無ければ `/new-song` を先に案内する。
3. `scripts/reference_run.sh <song> <url> --dry-run` で確認 → 実行(音声取得 → 音源分離 → MIDI 書き起こし → 分析)。初回は数分かかる(MuScriptor の重み取得と書き起こしに時間がかかる)。書き起こしが認証エラーで失敗したら、`docs/reference-analysis.md` の準備(Hugging Face のライセンス同意と `uvx hf auth login`)の手順をユーザーに提示して**ご自身で実行してもらう**(代行しない)。
4. `projects/<song>/reference/<id>/analysis.md` を読み、次の3点で報告する:
   - **わかったこと**: テンポ・キー(長調/短調)・コード機能の並び・盛り上がりの形・音の明るさ・刻みの細かさを、`docs/music-theory.md` の理論で平易に(初出用語は最大2つ、数値付き)。
   - **聴きどころ**: ユーザーが参考曲を聴き直して確かめる箇所(何秒付近)。推定の限界(テンポの倍/半分違い、コード推定の取り違え、書き起こしの不完全さ)を正直に伝える。
   - **次の選択肢**: 「この雰囲気で行く / 一部だけ取り入れる(例: テンポとコード機能だけ)/ 別の参考曲も分析する」(最大3)。
5. ユーザーが選んだ方向を `spec/00-concept.md` の下書き差分案として示す(承認前に spec を変更しない)。旋律・歌詞・リズムの丸写しは提案しない。
6. 結果と学んだ点を `notes.md` に追記する。
