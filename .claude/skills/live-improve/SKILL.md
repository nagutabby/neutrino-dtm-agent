---
name: live-improve
description: ユーザーが今鳴らしているコード(current.rb)を、小さな変更案(5案)で良くする。『もっと良くしたい』『この音どう?』『気になる』と言われたとき。
---

1. `work/current.rb` を読む(最新か不明ならユーザーに保存し直してもらう)。`work/notes.md` で制作スタイル(①自分で書く / ②AIが書く)を確認する。
2. ユーザーが気になる点を言っていればそれを最優先。無ければ AGENTS.md の「改善の観点」から**1観点だけ**選ぶ。ユーザーが具体的に指示したとき(「`amp` を下げて」など)は、案を出さずにその指示を実行する。
3. 案は**5つ**。各案は1つの変更で、狙いの違いが分かるように並べ(控えめ / 王道 / 大胆 / 別の方向 / 実験的)、**おすすめを1つ**理由つきで添える。コードの該当部分の before → after と数値(`cutoff: 80 → 100` など)で示す。`proposals/NN_<label>_<a〜e>.rb` に保存する。①は差分(貼り足し)、②は動く全体コード。①では `current.rb` は書き換えない。
4. 各案を `uv run scripts/live_check.py work/proposals/NN_<label>_x.rb` に通す。試聴が有益なら録音前に一言断り、**違いが大きい案とおすすめ案に絞って**短い区間で `live_render.py` を実行し、`wav_stats.py` で数値を見る。値が決めにくいとき(EQ・音量)は、短い試験録音で数値を比べる。
5. 「何が変わるか / なぜ(理論+数値)/ 聴きどころ(何秒付近)/ 試せる課題」を短く。②ではコードの読み方も添える。再生コマンドを添える。
6. 採否を聞き、`work/notes.md` に1行追記する。**採用が決まったら**、①はユーザーが貼り替える(依頼されたときだけ `current.rb` を更新)、②は旧版を `work/history/` に退避して `current.rb` を更新する。続けて `learning-log` スキルで学習ログに追記する(選ばなかった案は「何が違ったか」を1行)。
