---
name: live-next-stem
description: 今の音に重ねる次のステム(ドラム・ベース・コード・メロディ・装飾の1本)を、Sonic Pi のコードで5案提示する。『次は何を足す?』と聞かれたとき。
---

1. `work/current.rb` と(あれば)`work/notes.md` を読み、制作スタイル・ジャンルと選ばれた技法(`notes.md` の `技法:`)・鳴っているステム・BPM・キー/スケール・コード進行を把握する(推測で変えない。読み取れなければ聞く)。
2. 足りない要素を1つ特定する(リズム→低域→和声→旋律→装飾が既定の順。足りない帯域・拍位置を根拠に)。**足すのは1本だけ**。ユーザーが具体的に指示したとき(「ベースを足して」「clap を追加」)は、案を出さず、その指示を実行する。
3. 案は**5つ**(同じ役割で、違う音色/リズム/動き/音域/密度)。狙いの違いが分かるように並べ、**おすすめを1つ**理由つきで添える。コードを扱うときは `notes.md` の `つなぎ:` の技法を使い、使った箇所を示す。各案が選ばれた技法にどう沿うかを一言で添える(技法を勝手に足し引きしない)。各案は単体の `live_loop` として `proposals/NN_<stem>_<a〜e>.rb` に保存(スタイル②は、重ねた全体コードでもよい)。コード進行・キー・BPM は `current.rb` に合わせる。他人の旋律の複製はしない。
4. `live_check.py`(Sonic Pi の API と `docs/coding-rules.md` の書き方を検査。誤りは直す)を通し、`live_render.py current.rb proposals/NN_….rb --seconds N` で重ねて録音(録音前に一言断る。**違いが大きい案とおすすめ案に絞り、短い区間で**)。`wav_stats.py` で重ねる前後の帯域・音量を比較する。
5. 解説: 役割、既存ステムとのかみ合わせ(キックとベースの位置、音域の住み分け)、理論+数値、聴きどころ、試せる課題。②ではコードの読み方も添える。再生コマンドを添える。
6. **ボーカル(ボコーダー風)** を頼まれたとき、またはメロディが揃った後の任意枠: AGENTS.md「ボーカル」節に従い、既定は NEUTRINO(`~/neutrino`)で歌わせてボコーダー変換した wav を `sample` で載せる(日本語の響き重視)。英語の響きや軽く試したいときは、内蔵の `docs/vocal-helper.rb` の `vsing` を proposals に貼り、ローマ字の音節(意味のない響き重視、日本語・英語可)で歌詞を書く。案は例: ①母音だけの "ooh/aah" 伸ばし ②短い音節のリズムチョップ ③コール&レスポンス ④ハモリ(3度上/下) ⑤刻み(シンコペーション)。音高は `current.rb` のキーのコードトーン上、音域はメロ・ピアノと被らない MIDI 55〜72 を既定に。母音の聞き分けは聴いて確かめる箇所を示す。
7. 8小節ほどのループ(ドラム・ベース・コード)が揃ったら、展開を決めるために `live-structure` スキルでセクションごとの進行と内容をユーザーに聞く(曲を完成させるまでに必ず)。
8. 採否を聞き、`work/notes.md` に追記。**採用が決まったら**、`learning-log` スキルで学習ログに追記する(②は AI が書いたコードの全技法・用語を含める)。次のステムは次のターンで(1回に1本)。
