---
name: live-review
description: 曲が一通りできたとき(『できた』『レビューして』)、全体を録音して数値と理論で最終レビューする。
---

0. **構成の確認**: `uv run scripts/check_structure.py --final` を実行する。誤り(未確認のセクション・表なし・変化不足)があれば、録音の前に `live-structure` スキルでユーザーに聞く。結果はそのまま伝える。
1. `work/current.rb` を `live_check.py` に通す。曲の長さの代表区間を `live_render.py current.rb --name final --seconds N` で録音(展開が `sleep` や `tick` で長い場合は複数区間)。録音前に一言断る。
2. `wav_stats.py` で数値を取る(ピーク/RMS/帯域比/左右相関/窓ごとの RMS)。
3. レビュー(AGENTS.md「最終レビュー」の観点)。選ばれた技法(`notes.md` の `技法:`)と、コードのつなぎ(`つなぎ:`)が曲全体で一貫して使われ、滑らかに聞こえるか(隣接コードの共通音数・移動半音数)も観点に入れる。気になる点は重要度順に最大5件、各件に根拠(数値かコードの行)・具体的なコード変更・副作用。聴かないと言えない点は「未確認」+聴く箇所(何秒付近)。良かった点を2つ。
4. 再生コマンドを添える。直すかはユーザーが決める。直す場合は `live-improve` の流れ(1観点ずつ)へ。
5. **学習ログの仕上げ**: 曲で使った技法・用語のうち、`docs/learning-log.md` にまだないものを、`learning-log` スキルでまとめて追記する(追記してよいか聞かず、追記したエントリ番号を伝える)。決定と学びは `work/notes.md` にも1行足す。
6. 公開するとき(SoundCloud の説明欄など)は、「どこまでが人の判断で、どこまでが AI の補助か」を、`notes.md` のスタイルの記録に合わせて、一言で書くよう勧める。
