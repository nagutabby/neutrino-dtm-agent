---
name: live-start
description: ユーザーが Sonic Pi のライブコーディングで曲を始めるとき。制作スタイル(自分で書く / AI が書く)を選んでもらい、現状(テンポ・キー・鳴っているステム・足りない要素)を把握する。
---

1. `scripts/setup.sh` で環境を確認(✘ があれば直し方を伝えて止まる)。
2. **制作スタイルを1問だけ聞く**(`work/notes.md` の先頭に `スタイル:` の行がなければ): 「① 自分でコードを書く(AI は提案と解説)/ ② AI がコードを書く(あなたは聴いて方向を決める)のどちらにしますか。途中でも変えられます」。答えを `work/notes.md` の先頭に `スタイル: ①自分で書く` または `スタイル: ②AIが書く` と書く(ファイルがなければ作る)。答えがなければ ① とする。AGENTS.md「制作スタイル」を参照。
3. **ジャンルと技法を聞く**(`work/notes.md` に `ジャンル:` `技法:` の行がなければ。AGENTS.md「ジャンルと技法の確認」):
   - まずジャンルを自由記述で1問(候補は出さない)。
   - 答えを受けて、そのジャンルで主に使われる技法を5〜8個、括弧つきの一言説明で挙げ、**複数選択**で選んでもらう。**自由に追加・指定もできる**と伝える(「なし」「あとで」も可)。
   - 答えを `notes.md` に `ジャンル:` `技法:` の行で記録する。
4. 始める:
   - **①**: ユーザーのコードを `work/current.rb` に保存してもらう(貼ってもらえば AI が保存してよい。既存の内容があれば上書き前に確認)。空なら、狙い(雰囲気・テンポ・キー)を自由記述で1問だけ聞く。候補・例は出さない。
   - **②**: 狙い(雰囲気・テンポ・キー)を自由記述で聞く(足りない項目だけ)。聞いたら、ドラム(ビート)から1本ずつ書き始める(`live-next-stem`)。`work/current.rb` に既存の内容があれば、上書きせず、`work/history/` に退避してよいか聞く。
5. `uv run scripts/live_check.py work/current.rb` を通し、コードを読んで BPM(`use_bpm`)・キー/スケール・鳴っているステム(`live_loop` ごと)を把握する。読み取れない項目は本人に聞く。
6. 曲を完成させるまでに、セクションごとのコード進行と内容を `live-structure` スキルで必ずユーザーに聞く(8小節ほどのループができた段階で。遅くとも最終レビューの前)。
7. 現状を3行で要約し、次の選択肢を伝える: ① 今の音を改善 / ② 次のステムを提案 / ③ 自分で進める(スタイル①のみ)。決めるのはユーザー。
