---
name: genre-research
description: ユーザーが選んだジャンルの特徴(テンポ・ノリ・構成・尺・ミックスの傾向)を調べ、ユーザーが指示したトラック・音・コード進行と合わせて曲に反映する。トラック案・音色案は出さない。
---

前提: ジャンルはユーザーに聞いて決まっている(推測しない)。

1. **既存の定義は無い前提**: ジャンル別の定義・トラック構成は用意していない。曲ごと、毎回調べる(同じ曲の `projects/<song>/genre/` に既にあれば再利用してよい)。
2. **調べる**: WebSearch で、そのジャンルの ①テンポ帯とノリ(ハーフタイム/スウィング等) ②リズムの型 ③典型のスケール ④標準的な曲構成と尺 ⑤ミックスの傾向 を確認する。複数の情報源で裏を取り、確信のない点は「推定」と書く。`docs/genres/_template.md` を元に `projects/<song>/genre/<id>.md` を作る。**`tracks`(トラック案)・音色案・コード進行案は書かない**(コード進行・トラックの音はユーザーが最初に指示する。AI はサジェストしない)。
3. **ユーザーに見せて確認**: 特徴を5〜8行にまとめ(初出の専門用語は括弧で補足)、標準の長さ・構成を示して、ズレがないか聞く(選択肢は最大3)。`run_mode: auto` は聞かずに見せて進み、ズレの確認は最終報告に回す。曲名を例に出すのは確信のある有名曲だけ。旋律・歌詞・リズムの複製は提案しない。
4. **反映**: `projects/<song>/user_inputs.yaml`(ユーザー指示のトラック・音・コード進行)と、その音を作った `projects/<song>/synth/`(この曲専用のパッチ)が揃っていることを確認し、先に `uv run scripts/genre_apply.py <song> <id> --length-seconds <秒> --run-mode <step|auto> --dry-run`、問題なければ実行。出力の「曲の長さ → 小節数」を `01-structure` の決定材料にする。
5. **パッチ検査**: `genre_apply.py` の最後に `patches.py check` が走る。終了コード 2 なら表示されたエラー(他の曲の音色参照・サンプルの置き場違い・引数不一致など)を直してから続ける。
6. パッチの引数は `uv run scripts/patches.py show <song> <id>` で調べ、トラック spec の `patch_params` を決める根拠にする(音色の微調整もユーザーの言葉が根拠。AI の好みで変えない)。
