name: sound-qa
description: 全トラック作成後、ユーザーに提示する前に、Haiku 5.5 のサブエージェントで雑音の有無と全体の統一感をチェックし、問題があれば spec を直して再生成する。
---

全トラックの作成後、**ユーザーへの提示(最終まとめ・`mix-review`)より前**に実行する。`step` でも、トラック単位の提示は従来どおりで、このチェックは最後のトラックの作成後に1回走らせる。

1. **チェック依頼**: `docs/sound-qa-prompt.md` の役割プロンプトを埋め、`Agent` ツールを `model: "haiku"`(`claude-haiku-5-5`)で起動する。読み取りのみ。
2. **判定**: 先頭が `問題なし` なら終了。`要修正` なら、指摘を数値(`ffmpeg` の `astats` / `volumedetect`、`explain_midi.py` など)と spec で裏取りする。**数値と矛盾する指摘は採用しない**(理由を `decisions` か `notes.md` に1行)。
3. **修正**: 採用分を `spec-revise` の流れで直す(spec の差分案 → version+1 → 影響範囲の一覧)。生成物は直接直さない。`step` は差分案への了承を得てから、`auto` は止まらず進める。
4. **再生成と再チェック**: `patches.py check` を通し、`spec-regenerate` で該当トラックと下流・ミックスだけ作り直して手順 1 へ(最大 2 周。消えなければ `step` は残った指摘と原因を報告して指示を仰ぎ、`auto` は最終報告に回して進む)。
5. **終了**: 周ごとの指摘件数と変更点を `notes.md` に追記。未確認の点は「聴いて確かめる箇所(何秒付近)」と `scripts/play.sh` の再生コマンドでユーザーに渡す。その後 `mix-review` に進む。

音は聴けないので、判定は数値ベース。聴感の最終判断はユーザーに委ねる。
