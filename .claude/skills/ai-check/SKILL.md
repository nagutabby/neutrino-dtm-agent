---
name: ai-check
description: トラック生成後・最終ミックス後に、AI 生成音楽にありがちな問題(ループの貼り合わせ・起伏のなさ・機械的な強弱・帯域の偏り・ステレオの狭さ)を数値でチェックし、サブエージェントのレビューを受けて、警告がすべて消えるまで spec を直して再生成する。
---

警告が 0 件になるまで次のループを回す(最大 5 周。5 周で消えなければ、残った警告と原因をユーザーに報告して指示を仰ぐ)。

1. **検査**: `uv run --group reference scripts/ai_check.py <song> --all`(MIDI だけなら `--midi tracks/NN_x_vN.mid`、ミックスだけなら `--mix mix/stepN_vN.wav`)。基準と直し方は `docs/ai-music-pitfalls.md`。警告を「何が/なぜ/直し方」で伝える。
2. **レビュー(必須)**: `Agent` ツールで `model: "haiku"` のサブエージェントを起動する(Claude Haiku 5.5 = `claude-haiku-5-5`。`haiku` が 4.5 などの旧版に解決される場合は、`model` に `claude-haiku-5-5` を明示する)。渡すもの: 警告の全文、`docs/ai-music-pitfalls.md`、関係する spec(`projects/<song>/spec/` の対象と `depends_on` だけ)、区間ごとの音量(4秒または区間単位の dB)。依頼内容: 「警告の原因の見立て」「spec のどの値を before→after でどう変えるか」「他の警告を悪化させる副作用」を短く返す(読み取りのみ。ファイルを編集させない)。レビューは参考であり、数値と矛盾する指摘は採用しない。自動で測れない項目(無難な和声・主役の不在)はレビューにも見立てを求め、聴きどころを添えてユーザーに確認する。
3. **修正**: レビューに基づき `spec-revise` の流れで直す(spec の差分案 → version+1 → `decisions` に理由 → 影響範囲の一覧)。生成物は直接直さない。`run_mode: step` はユーザーに差分案を見せて了承を得てから、`auto` は止まらずに進め、最後に変更点をまとめて報告する。
4. **再生成**: `spec-regenerate` で該当トラックと下流・ミックスだけ作り直す(`patches.py check` を先に通す)。
5. **再検査**: 手順 1 に戻る。1 回の修正で悪化した項目(例: 谷の区間が逆に大きくなった)が出たら、元に戻さず次の周で直す。
6. **終了**: 警告 0 件になったら、各周の警告件数の推移と最終の変更点を `notes.md` に追記し、聴きどころ(何秒付近)と再生コマンドを添えて報告する。ジャンルの特性で外す項目は理由を `decisions` に残してから外す(その場合の警告は 0 件扱い)。

`run_mode: step` はトラックごとの技術解説のあとに 1 周目、`auto` は最終ミックスのあとに実行する。
