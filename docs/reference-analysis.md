# 参考曲の分析(YouTube → 音源分離 → 音声の分析。参考曲+類似曲を few-shot の例にして雰囲気を言語化)

目的: 「こんな雰囲気の曲を作りたい」を、参考曲と類似曲に共通する**抽象的な特徴**に翻訳して `spec` に反映する。コーチの対話の材料であり、曲をまねるための機能ではない。

## 使い方
`/reference <song> <YouTube URL>`。方針: **MIDI の検索・取得・書き起こしはしない**。ユーザーの参考曲(`seed`)に加え、ジャンル確定後に Web 検索で見つけた**類似曲(`similar`、最大3曲)**も YouTube から取得し、同じ手順(取得 → 音源分離 → 分析)で数値化する。複数曲の結果を並べたものが few-shot の「例」で、共通点をそのジャンル・雰囲気の型として扱う。

### 1. 参考曲の音声(`scripts/reference_run.sh <song> <url>`)
次の3段階を順に実行する(個別実行も可):

| 段階 | スクリプト | 出力(`projects/<song>/reference/<video-id>/`) |
|---|---|---|
| 取得 | `reference_fetch.sh` | `audio.wav`、`source.json`(タイトル等) |
| 音源分離 | `reference_separate.py`(Demucs **htdemucs_6s**。`--model htdemucs` で4パート) | `stems/{drums,bass,other,vocals,guitar,piano}.wav`(コード・キー・リズムの推定用) |
| 分析 | `reference_analyze.py`(librosa) | `analysis.json`、`analysis.md` |

音源分離は初回にモデル(約80MB)を取得する。CPU で曲の長さの0.5〜1倍ほどかかる。省く場合は `REF_SEPARATE=0`。
必要なもの: `brew install yt-dlp ffmpeg`。Python 依存は `uv sync --group reference`(`uv run --group reference` で自動)。

### 2. 類似曲(ジャンル確定後。Web 検索 → 同じ手順で分析)
1. エージェントが WebSearch で探す。検索語は「ジャンル + 参考曲の分析から推定した雰囲気(テンポ帯・長調/短調・明るさ・盛り上がり)」。
2. **YouTube の単体動画(10 分以内)の URL が確認できる曲**を最大3曲。一覧(曲名 / アーティスト / URL / 似ている点)をユーザーに見せる。参考曲そのものは入れない。
3. 1曲ずつ `scripts/reference_run.sh <song> <url> --role similar`。`reference/<id>/role` に区分が残る。再生リスト・チャンネルの一括取得はしない。

### 3. few-shot の例にまとめる(`uv run scripts/reference_summary.py <song>`)
`projects/<song>/reference/summary.md` に、曲ごとの数値表(テンポ・キー・よく出る4小節・明るさ・刻み)と共通点(テンポ帯・長調/短調の割合・多いコード機能・4小節進行・盛り上がりの平均形・パート比)を出す。共通点は2曲以上の例があるときだけ「型」と言える。旋律・音符列は出力しない。

類似曲は参考曲そのものではなく、分析にも誤差がある。複数曲に共通する傾向だけを spec 立案の根拠にし、違いはユーザーが選ぶ余地として提示する。

## 聴く
分離した各パートや元音声は `scripts/play.sh --list <song>` で一覧し、`scripts/play.sh projects/<song>/reference/<id>/stems/vocals.wav` で聴く(スペース=一時停止、←→=移動、q=終了)。分離の出来(混ざり・欠け)を耳で確かめてから分析結果を信じる。

## 分析する特徴
テンポ / キー(長調・短調)/ 小節ごとのコード(ローマ数字=機能で表示。短調は平行長調基準)/ 盛り上がりの形(8分割の音量)/ 音の明るさ / 刻みの細かさ。パート別の音量比(分離後)。複数曲は reference_summary.py で共通点を出す。
旋律・歌詞・音符列そのものは出力しない。

## 音源分離の効果(合成音源での検証)
正解の分かる16小節(C-G-Am-F ×4、100 BPM、ドラム・ベース・ピアノ・メロディ)で比較した結果:

| 項目 | 分離なし | 分離あり |
|---|---|---|
| コード(小節ごと、位置ずれ許容) | 14/16。Am の重複など進行が乱れる | **16/16**。C-G-Am-F が全周で一致 |
| テンポ | 99.4 BPM | 99.4 BPM(正解100) |
| キー | C 長調 | A 短調(平行調。ローマ数字の基準は同じ) |

分離ありのコード推定は、**根音をベースのパート、長調/短調を和音パート(other)の3度**から決める。ベースの倍音(5倍音=長3度)に惹かれて A を A(長)と誤る問題を避けるため。
(経緯)音声の MIDI 書き起こし(Basic Pitch、MuScriptor)も試したが、ベース・和音の取りこぼしが大きく(再現率 25〜38%)、実曲での精度も測れないため廃止した。MIDI の検索・取得も廃止し、類似曲は YouTube から取得して音声で分析する(採譜者の解釈を含む MIDI より、参考曲と同じ手順で揃えられる)。

## 6パート分離(htdemucs_6s)について
- 既定は 6 パート版。ピアノとギターが `other` から分かれる。コード・キーの推定は bass と、other + guitar + piano の合算を使う。
- 開発元が実験的としており、**ピアノ・ギターの分離は不安定**。実曲(ギター中心の曲)では、主役のギターが guitar パートには 1% しか入らず、`other` に残った。ピアノは約 6% 分離されたが、取りこぼしや漏れは未検証(聴いて確認する)。
- 分離を変えてもコード進行の推定精度は変わらなかった(キーの音階に収まるコードの割合 0.63 → 0.61)。コードの散らばりの主因は拍の揺れ(固定の小節区切りがずれる)と考えられる。
- 4 パート版が欲しい場合は `reference_separate.py ... --model htdemucs`。

## 精度の限界(必ずユーザーに伝える)
- 類似曲は参考曲そのものではない。複数曲に共通する傾向を拾う。
- テンポは倍/半分に誤検出することがある。コード推定は旋律や転調で外れる。
- 推定値はユーザーの耳で確認してから spec に反映する。

## 守ること(厳守)
- **私的な参考分析に限る**。YouTube の利用規約と著作権法を守り、取得する権利のあるコンテンツだけを対象にする。ダウンロードの責任はユーザーにある。
- 取得した音声・分離音・分析結果・出典(`reference/` 配下)は**すべて私的な分析用で、コミット・公開・再配布しない**(`projects/*/reference/` は `.gitignore` 済み)。
- 類似曲も同様に私的な分析用。1曲ずつ取得し、一括取得はしない。
- 参考曲の**旋律・歌詞・特徴的なリズムパターンを複製しない**。取り入れるのはテンポ感・キーの長短・コード機能の並び・盛り上がりの設計などの一般的な要素まで。
- 「AI が学習する」は、分析結果を材料にコーチが対話することを指す。モデルの学習・ファインチューニングはしない。
- NEUTRINO の出力音声・中間データを参考曲として分析しない(`docs/licensing.md`)。
