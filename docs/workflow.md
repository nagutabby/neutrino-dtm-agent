# ワークフロー

0. **制作スタイルを選ぶ**(`live-start`): ① 自分でコードを書く(AI は提案と解説)/ ② AI がコードを書く(ユーザーは聴いて方向を決める)。途中で切り替えてよい。`work/notes.md` の先頭に記録。
1. 曲を始める: ① ユーザーがコードを `work/current.rb` に保存して伝える / ② ユーザーが狙い(雰囲気・テンポ・キー)を言い、AI が書き始める(`live-start`)。
2. 繰り返す: **今の音を改善**(`live-improve`)または**次のステムを提示**(`live-next-stem`)。案は **5つ**(狙いの違う案 + おすすめ1つ)を `work/proposals/` にコードで置き、必要なら短い区間で録音して試聴。具体的な指示は、案を出さず実行する。採否はユーザーが決める。
3. **採用が決まったら学習ログへ**(`learning-log`): 音楽理論に基づく意味と、使った技法・用語を `docs/learning-log.md` に残す(後から検索できる)。
4. 8小節ほどのループができたら、**構成の確認**(`live-structure`): セクションごとのコード進行・雰囲気・楽器・つなぎをユーザーに聞き、`work/structure.md` に記録する(ユーザーが了承した行に ✔)。`uv run scripts/check_structure.py` で検証。**曲を完成させるまでに必ず**。
5. できたら**最終の全体レビュー**(`live-review`)。最初に `check_structure.py --final` を実行し、誤りがあれば構成を聞き直してから録音する。
