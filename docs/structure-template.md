# 曲の構成(セクションごとのコード進行と内容)

曲が単調にならないように、**セクションごとに、雰囲気・コード進行・鳴らす楽器・つなぎ方を、ユーザーと決める**。決めた内容は `work/structure.md` に表で残し、ユーザーが了承した行に `✔ 日付` を付ける。検証は `uv run scripts/check_structure.py`(途中)/ `--final`(完成前)。AI が勝手に ✔ を付けてはいけない。

## 書式(`work/structure.md`)
```markdown
# 構成
キー: Fマイナー / BPM: 145

| セクション | 小節 | 雰囲気・役割 | コード進行 | 鳴らす楽器 | つなぎ | 確認 |
|---|---|---|---|---|---|---|
| イントロ | 1-8 | 静かに漂う | Fm7→Fm7→Dbmaj7→Dbmaj7 | ピアノ | riser | ✔ 2026-10-12 |
| ビルドアップ | 9-16 | 緊張を溜める | Bbm7→Dbmaj7→Ebmaj7→C7 | ピアノ・ドラム | 最後の1拍を無音に | ✔ 2026-10-12 |
| ドロップ | 17-32 | 開放感 | Fm7→Dbmaj7→Abmaj7→Ebmaj7 | 全部 | クラッシュ | |
```
- コード進行は `→` でつなぐ(1コードなら `Fm7` の1つだけでもよい)。小節は `1-8` の形。
- 「確認」が空の行は、ユーザーにまだ聞いていない(または了承されていない)行。
- セクションを足す・進行を変えたら、行を更新して、確認(✔)をもう一度もらう。

## 聞くこと(セクションごと)
1. **長さ**(小節)
2. **雰囲気・役割**(静か / 緊張 / 開放 / 浮遊 / 締め など)
3. **コード進行**(下の候補から5案出して選んでもらう。前後のセクションと変化を付ける)
4. **鳴らす楽器**(何を入れて、何を抜くか。「音を引く」も選択肢)
5. **つなぎ**(riser / 無音の拍 / フィル / クラッシュ / なし)

## コード進行の候補(マイナーキーの例。F マイナーの場合のコード名つき)
| 狙い | ローマ数字 | F マイナーでの例 | 聞こえ方 |
|---|---|---|---|
| 安定・漂う | i → i → VI → VI | Fm7 → Fm7 → Dbmaj7 → Dbmaj7 | 動きが少なく、静か |
| 開放・王道 | i → VI → III → VII | Fm7 → Dbmaj7 → Abmaj7 → Ebmaj7 | 明るく開ける。future bass の定番 |
| 緊張 | iv → VI → VII → V7 | Bbm7 → Dbmaj7 → Ebmaj7 → C7 | 上へ登って、V7 が主和音への解決を呼ぶ |
| 浮遊・明るい | III → VII → iv → V7 | Abmaj7 → Ebmaj7 → Bbm7 → C7 | 平行長調(Ab)寄りで浮く |
| 締め・解決 | i → VI → iv → V7 | Fm7 → Dbmaj7 → Bbm7 → C7 | 最後に V7 → i で落ち着く |
| 暗く沈む | i → iv → VII → III | Fm7 → Bbm7 → Eb7 → Abmaj7 | 下へ向かい、重い |

- ローマ数字は、キーが変わっても同じ形で使える(`docs/music-theory.md`)。
- セクションごとに進行を変えると、曲の雰囲気が単調にならない。同じ進行を繰り返すセクションは、楽器の出し入れやリズムで変化を付ける。
- 候補は例。ユーザーの案があれば、それを優先する。
